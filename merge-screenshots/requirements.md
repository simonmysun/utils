# 截图合并工具 - 需求文档

## 项目概述
开发一个单页面应用，允许用户上传多张手机截图并智能合并成一张连续的拼接图。主要面向从长文档或网页中截取的多张截图的拼接场景。

## 术语与坐标模型
为避免实现时产生歧义，统一以下定义：
- **拼接轴**: 图片排列的方向。垂直拼接时拼接轴为纵向；水平拼接时拼接轴为横向。
- **拼接轴垂直边**: 与拼接轴垂直的那条边。垂直拼接时为图片**宽度**；水平拼接时为图片**高度**。
- **边缘裁剪 (edge crop)**: 每张图片上下左右四个方向可独立设置的裁剪像素数，裁剪后剩余区域参与拼接。
- **重叠接缝 (overlap seam)**: 相邻两张图片在拼接方向上重叠的区域。重叠**等价于自动增加"前一张图片"在拼接方向末端的边缘裁剪**（见 3.3）。

## 核心功能需求

### 1. 图片管理模块
- **图片上传**: 支持用户选择多张图片文件上传
- **图片加载器**: 抽象出图片加载类，便于后续扩展不同的加载方式
- **支持格式**: 常见图片格式（PNG, JPG, WEBP等）
- **图片显示**: 在编辑界面中显示已上传的图片

### 2. 图片操作模块
- **排列方向控制**:
  - 用户可选择水平拼接或垂直拼接
  - 支持图片旋转（90度增量）
- **顺序调整**: 用户可以调整图片在序列中的位置
- **增删操作**: 支持添加新图片和删除已有图片

### 3. 图片编辑模块
- **尺寸一致性约束**:
  - 要求所有参与拼接的图片在**拼接轴垂直边上像素尺寸完全一致**（垂直拼接要求宽度相同，水平拼接要求高度相同）
  - 不满足时直接报错，不做缩放/重采样
- **边缘裁剪**:
  - 可调整每张图片四个边缘的裁剪距离
  - 提供像素级精度控制
- **接缝调整（重叠）**:
  - 编辑流程为**先做边缘裁剪，再做重叠接缝**
  - 相邻图片可在拼接方向上重叠
  - 重叠在数据模型上等价于自动增加**前一张图片**在拼接方向末端（垂直拼接时为下边缘，水平拼接时为右边缘）的裁剪量；分界线位置即该裁剪量的可视化调节
  - 实时预览调整效果

### 4. 智能合并功能（P2，已实现）
- **重复内容识别**:
  - 自动识别图片头尾的**固定区域**（如状态栏、网页头部、底部导航栏、固定壁纸）
  - 自动识别相邻截图之间的**滚动重叠量**
- **智能裁剪建议**:
  - 根据识别结果自动填充每张图片的裁剪量与重叠量（"Auto-merge" 一键应用）
  - 识别结果仅作为**建议**，用户始终可接受或手动覆盖（所有值仍是普通可编辑的裁剪/重叠）
- **可插拔接口**: 通过 `SuggestionProvider.analyze(items, direction, { allowReorder })` 批量接口接入，返回 `{ order, perItem:[{ cropTop, cropBottom, overlapNext }], warnings }`，可在不改动核心编辑/合并流程的前提下替换算法实现。

#### 4.1 智能合并算法
面向"同一设备、同一场景、连续向下滚动"的截图序列，核心是**沿拼接轴的一维对齐**，而非二维裁剪×重叠穷举：

1. **光栅化**: 按各图当前旋转角把像素画到画布，取亮度 `luma = .299R+.587G+.114B`。水平拼接时把矩阵转置，使算法只需处理"沿拼接轴 = 行"这一种情况。
2. **降维签名**: 沿拼接轴垂直方向把每一"行"下采样为 `K`（默认 32）个列块均值，得到每张图的签名矩阵 `S_i[A][K]`（`A` = 沿轴长度）。列块化能突出稀疏内容（如聊天气泡），并大幅降低计算量。
3. **时间中值背景**: 对所有图取逐元素中值 `med = median_i(S_i)`，作为"固定背景"（状态栏、固定壁纸等在所有图中不变）。残差 `Rᵢ = Sᵢ − med` 只保留滚动内容，是更严格且更通用的匹配特征（各处波谷更锐利）。
4. **固定头/尾检测**: 令 `rowdev[a] = mean_i mean_k |Sᵢ[a][k] − med[a][k]|`，用相对阈值 `tol = P10 + 0.4·(P70 − P10) + 2` 取**开头/结尾连续低于阈值**的行数作为固定头 `ht` / 固定尾 `hf`（容忍状态栏时钟等微小抖动）。滚动区间为 `[ht, A − hf]`，长度 `As = A − ht − hf`。
5. **相邻对齐**: 对每对相邻图，在滚动区间残差上以位移 `s ∈ [minScroll, As − minOverlap]` 做**归一化互相关 (NCC)**，取最优 `s`。用 NCC（而非 SSD）可避免"两侧残差都≈0"时坍缩到退化的最小重叠匹配；`minScroll` 地板则排除零位移伪匹配。
6. **置信度**: 记录最优 NCC 峰值，低于阈值（默认 0.5）时对该接缝发出 `warnings`，但仍给出建议供用户调整。

对第 `k` 张（共 `n` 张）图生成计划：
- `cropTop = (k==0) ? 0 : ht`
- `cropBottom = (k==n-1) ? 0 : hf`
- `overlapNext = (k==n-1) ? 0 : (As − s_k)`（在数据模型上折叠进"前一张图"末端裁剪，见 3.3）

`allowReorder` 为真时，用两两最优 NCC 贪心串成一条链后再对齐（默认关闭）。

### 5. 导出功能
- **图片合成**: 将编辑后的多张图片合并为单张图片
- **格式输出**: 输出 PNG 格式
- **下载功能**: 通过 `Blob` + `<a download>` 触发浏览器下载保存最终图片

## 技术需求

### 1. 开发约束
- **单页面应用**: 所有功能围绕一个 HTML 页面实现
- **技术栈**: 仅使用原生 HTML + CSS + JavaScript，**不使用任何框架，不使用构建工具**
- **模块化**: 使用原生 ES Modules（`<script type="module">` + `import`/`export`），**允许拆分为多个 `.js` 文件**
- **运行方式**: 通过本地 HTTP Server 打开（如 `python -m http.server`）；**不需要支持 `file://` 直接双击打开**（多文件 ES Module 在 `file://` 下受 CORS 限制无法工作）
- **跨平台**: 支持桌面端和移动端浏览器

### 2. 渲染策略
- **预览与编辑阶段**: 优先使用 CSS/DOM 实现（如 `object-fit`、`clip`/`overflow` 裁剪、`transform` 旋转、定位实现重叠），避免不必要的 Canvas 开销
- **导出阶段**: 合成为最终图片时使用 Canvas，再通过 `toBlob` 输出 PNG

### 3. 性能与限制
- **不预先设计性能上限**: 图片数量、尺寸等一切限制依赖浏览器实现，不做人为约束
- **已知客观限制（仅记录，不额外处理）**: Canvas 单边尺寸存在浏览器硬上限（多数浏览器约 16384px，部分浏览器更低），超限时导出可能失败——该情况按下述错误处理策略处理
- **实时预览**: 编辑操作应提供实时预览效果

### 4. 错误处理策略
- 遇到不满足约束或运行时错误（如尺寸不一致、格式不支持、Canvas 导出失败等）时，**直接报错并中止**，由用户刷新页面重来；不做复杂的容错或恢复

### 5. 浏览器兼容性
- 支持现代浏览器的 Canvas API
- 支持 File API 用于图片上传
- 支持 Blob API 用于图片下载
- 支持原生 ES Modules

### 1. 基本布局
- **上传区域**: 图片选择和上传界面
- **编辑区域**: 图片序列显示和编辑工具
- **控制面板**: 操作按钮和参数调整控件

### 2. 交互设计
- **界面语言**: 英语（English）

- **状态反馈**: 显示处理进度和操作结果

## 实现优先级

### P0 (核心功能)
1. 图片上传和显示
2. 基本的顺序调整和增删操作
3. 简单的边缘裁剪功能
4. 基本的图片合并和下载

### P1 (增强功能)
1. 接缝位置调整（重叠）
2. 图片旋转功能
3. 排列方向选择
4. 更精细的编辑控制

### P2 (智能功能)
1. 重复内容自动识别
2. 智能裁剪建议
3. 高级图像处理算法

## 可扩展性考虑
- 图片加载器设计为可插拔架构
- 图像处理算法模块化，为智能合并预留足够接口
- 预留接口用于未来功能扩展（如批量处理、云存储等）

## 非目标 (Out of Scope)
- **数据持久化**: 刷新页面后编辑状态**不保留**
- **撤销 / 重做**: 本期不实现（标记为未来可选功能）
- **隐私 / 安全说明**: 不作为需求关注点
- **性能上限设计**: 不主动设计，交由浏览器决定
- **`file://` 直开支持**: 不支持
